# ChogCare: экран и LED на трансляции

Прошивка для **NodeMCU 1.0 (ESP-12E Module)** и цветного **ST7789 240×320**. Компьютер передаёт благодарность по USB после проверки квитанции поступления благотворительности существующим платёжным процессором. Показ благодарности отделён от окончательной финальности блокчейна.

Это не обработчик денег. Прошивка не знает кошельков, ключей, Wi-Fi-пароля или адреса платёжного API. Сайт и трансляция остаются на своей текущей схеме; публиковать плату или USB-порт в интернете не нужно.

## Обновление экрана ожидания (18 октября 2026)

Весь служебный текст на дисплее — на английском. Ожидание: **ChogCare → предоставленная владельцем иллюстрация со скруглёнными углами → Waiting for kindness**. Внизу — только пульсирующая точка и **LIVE**, без таймера. LIVE появляется только при положительном ответе публичного локального Owncast `/api/status`; проверка идёт раз в 5 секунд и не задерживает очередь благодарностей. При остановленном/недоступном эфире отображается **STATION ONLINE**, при пропавшем USB heartbeat — **CONNECTING**.

На втором экране, сразу после ожидания, сверху показано **Kindness received** с галочкой, ниже — крупное название инициативы. Короткие строки используют жирный шрифт 24 pt, длинные отдельные слова — 18 pt. Названия занимают от двух до четырёх строк и полностью видны без прокрутки. Последняя строка выделена розовым. Экран суммы и его точность сохранены. В финальной благодарности используется эта же иллюстрация со скруглением; ник, Thank you! и анимация сердец сохранены.

Исходная иллюстрация — `firmware/assets/chogcare-kindness.png`, готовые RGB565-массивы — `StationBrand.h` (94 720 байт во flash, дополнительный буфер RAM не нужен). Офлайн-пересборка: `node scripts/build-station-brand.mjs <папка-пакета-sharp>`, проверка — с `--check`. Генератор макета теперь также создаёт `work/station-art/station-preview.png` с ожиданием и всеми тремя сценами. Главные надписи рисуются настоящими шрифтами Adafruit; мелкие U8g2-подписи в макете приближённые.

Статус эфира согласуется отдельной возможностью `idle: 1` в hello/pong. Только такая плата получает булево поле `live` в ping; со старой прошивкой формат не меняется. Новый мост читает только локальный публичный статус Owncast без пароля. Адрес API и полные данные статуса на плату не передаются. После обновления прошивки переподключи только Care station в админке, чтобы мост загрузил новый код.

## Три сцены благодарности

Текущая прошивка показывает **Kindness received и название инициативы (6 с) → исходную сумму CHOG (4,5 с) → маскота, ник и Thank you! (4,5 с)**. Фотографии инициатив и рамки убраны по просьбе владельца. Название появляется сразу крупным текстом в две-четыре строки. Затемняющих переходов нет: между этапами не вставляется чёрный экран. LED — один обычный светодиод, поэтому меняется плавность яркости и ритм, а не цвет. Внизу экрана — прогресс, вверху — текущая сцена.

В ChogCare Admin 1.0.2: **Services → Care station → COM6 → Connect station → Test screen**. Чтобы мост подхватил обновлённый код, достаточно Disconnect → Connect station; перезапускать Payments или саму админку не нужно. При повторных тестах по очереди появляются пять инициатив. На всех тестовых сценах постоянно указано **TEST / NO PAYMENT**. Тест не создаёт счёт, не перемещает деньги, не попадает в историю и не перебивает настоящую благодарность.

`StationScenes.h` и офлайн-генератор фото сохранены как неиспользуемые исходные материалы предыдущего варианта; текущий дисплей их не подключает и не показывает. Монета из `StationArt.h` используется на экране суммы, иллюстрация из `StationBrand.h` — в ожидании и финале. Плате не нужен интернет.

Новый мост определяет поддержку сцен по `scenes: 2` в hello/pong. Со старой прошивкой автоматически используется прежний USB-формат. Уже сохранённые события очереди не переписываются; если старая запись не содержит инициативу, экран показывает нейтральную сцену, не выдумывая получателя. В новые события добавляется только идентификатор инициативы из фиксированного списка. URL, адреса кошельков и файлы через USB не принимаются.

`Cause delivery confirmed` означает проверенное поступление благотворительности, а не окончательную финальность блокчейна: её статус остаётся в квитанции на сайте. Показанная сумма — исходная выбранная сумма CHOG, не фактическая валюта, полученная инициативой после обмена и комиссий. Длинные точные суммы и ники прокручиваются один раз внутри своей сцены, без округления. Текущий показ занимает 15 секунд.

Для отдельной проверки платы при **отключённом** мосте админки: `node scripts/check-station-scenes.mjs COM6`. Проверка ждёт новый протокол и подтверждение завершённого тестового показа, не открывая платёжные базы. Программный макет сцен: `node scripts/preview-station-scenes.mjs <папка-пакета-sharp>`; он проверяет границы настоящих шрифтов Adafruit, но не заменяет проверку изображения камерой.

## 1. Подключение

Перед перестановкой проводов отключи питание/USB. **LED остаётся на D0, а провод RST экрана перенеси с D0 на D1.** Остальные провода экрана не меняй.

| ST7789 | NodeMCU |
| --- | --- |
| CS | D4 |
| DC | D2 |
| RST | D1 |
| SCLK / SCK | D5 |
| MOSI / SDA | D7 |
| VCC | 3V3 |
| BL | 3V3 |
| GND | GND |

Единственный внешний светодиод:

```text
D0 ──[1 кОм]── анод (+ LED −) катод ── GND
```

**LED и RST экрана нельзя подключать к одному пину.** В этой версии LED использует D0 / GPIO16, а RST экрана — D1 / GPIO5; резистор LED обязателен. Не подавай 5 В на GPIO. Обозначения SDA/SCL на этом TFT относятся к SPI, не к четырёхконтактному I²C-экрану. Назначения GPIO описаны в [документации ESP8266](https://arduino-esp8266.readthedocs.io/en/3.1.2/reference.html).

## 2. Прошивка в Arduino IDE

1. Открой `firmware/chogcare_station/chogcare_station.ino` из этой папки. Все `.h`, включая `StationArt.h` и `StationScenes.h`, должны остаться рядом с `.ino`.
2. В **Tools → Board** выбери **NodeMCU 1.0 (ESP-12E Module)** из установленного пакета ESP8266. Используй CPU 80 MHz, Flash 4 MB и обычную загрузку скетча, без полного стирания flash.
3. В **Tools → Port** выбери порт именно NodeMCU. На этом стенде подтверждён COM6. После переподключения USB сверь порт заново.
4. Через Library Manager установи **Adafruit GFX Library**, **Adafruit ST7735 and ST7789 Library**, **Adafruit BusIO**, **U8g2_for_Adafruit_GFX**. На текущем компьютере они уже установлены. ArduinoJson не требуется.
5. Нажми **Verify**, затем **Upload**. После загрузки закрой **Serial Monitor / Serial Plotter**, иначе USB-мост не откроет порт.

Ориентация сохранена из старого скетча: `tft.init(240, 320)` и `setRotation(0)`. Только если физически экран окажется перевёрнут на 180°, поменяй `ROTATION` на `2` в `StationConfig.h` и прошей снова; провода не меняй. Параметры поддерживаются [библиотекой ST7789](https://adafruit.github.io/Adafruit-ST7735-Library/html/class_adafruit___s_t7789.html).

Проверка компиляции из терминала, **без прошивки**:

```powershell
cd C:\Users\User\Documents\Codex\2026-10-07\ghb
npm run station:compile
```

## 3. Сначала тест без денег

После прошивки открой отдельный PowerShell в папке проекта при отключённом мосте админки. Используй подтверждённый порт NodeMCU:

```powershell
cd C:\Users\User\Documents\Codex\2026-10-07\ghb
npm run station:demo -- --port COM6
```

Это **демонстрация**, не настоящий платёж: экран показывает название Solar Foundation без фото → `300 CHOG` → `Thank you!`, а LED мягко светится 15 секунд. Скрипт завершится после подтверждения показа платой. Он не открывает платёжную базу и не отправляет транзакции. На экране постоянно видна тестовая пометка, поэтому такой тест нельзя представлять как реальный донат.

Проверка только протокола, вообще **без открытия USB**, тоже доступна:

```powershell
node scripts/station-bridge.mjs --demo --simulate
```

## 4. Настоящие пожертвования

Платёжный процесс оставь работающим и разблокированным в его текущем терминале. После демонстрации запусти USB-мост в отдельном окне:

```powershell
cd C:\Users\User\Documents\Codex\2026-10-07\ghb
npm run station -- --port COM6
```

Окно моста должно оставаться открытым. Ничего перезапускать в платёжном коде и ничего менять на Vercel для этого не требуется.

Дальше автоматически:

1. Процессор проверяет квитанцию поступления благотворительности: получателя, токен, сумму и канонический блок. Статус `confirming` с действующей квитанцией уже разрешает благодарность; финальность проверяется независимо. Сам исходный перевод токенов, ожидание моста и запись в лидерборде LED не включают.
2. Мост берёт выбранную сумму пожертвования. Например, при `300 + 30` для пула экран показывает **300 CHOG**, не 330. Это исходный размер пожертвования в CHOG, не сумма полученной благотворительностью валюты после обмена и комиссий.
3. Используется публичный ник из профиля донора. Если он ещё не сохранён, мост ждёт до 8 секунд; затем показывает `CHOG FRIEND`. Уже отправленный показ не меняется при позднем сохранении профиля. Кириллица поддерживается, латинские диакритические знаки упрощаются; имя ограничено 24 символами. NFT-картинки на TFT в этой версии не выводятся.
4. Последовательно появляются название выбранной инициативы без фото, исходная сумма CHOG, а затем маскот, ник и `Thank you!`. LED плавно загорается, мягко пульсирует и гаснет через 15 секунд. Следующее пожертвование не перебивает текущий показ, а ждёт очереди.

Финальное подтверждение платежа иногда занимает минуты и продолжает проверяться в фоне. Ранний показ не меняет финансовое состояние и не создаёт запись `delivered`. Если квитанция исчезла из канонической цепи или перестала проверяться, ещё не отправленная благодарность удерживается. Сохранённый идентификатор не допускает второй показ при переходе `confirming` → `delivered`.

**Эта версия реагирует на проверенное поступление CHOG-пожертвований.** Выплату NFT-пула в долларах она не превращает в выдуманное количество CHOG. Поддержку отдельного экрана для NFT-субсидий можно добавить отдельно.

## Перезапуск и безопасность

- При первом рабочем запуске мост запоминает текущий конец журнала: старые донаты не воспроизводятся. Запусти мост **до нового тестового пожертвования**.
- Очередь сохраняется отдельно в `work/station/station.sqlite`. Не удаляй её ради восстановления. Обычный перезапуск продолжает незавершённую очередь; после потери питания посреди показа одна незавершённая благодарность может повториться. Повторных денежных переводов мост не делает.
- SQLite-файлы платежей открываются только для чтения; их схема, состояние и контроль целостности не меняются. Мост не загружает финансовые ключи.
- На плату передаются только очищенный ник, сумма, непрозрачный идентификатор события и разрешённый идентификатор инициативы; для демонстрации — явный тестовый маркер. Адрес кошелька и данные оплаты не передаются и не появляются на экране.
- Wi-Fi платы выключен. Новый HTTP-сервер, публичный маршрут или входящий сетевой порт не создаётся. Мост проверяет платёжный процесс на `127.0.0.1:4174` и публичный статус существующего Owncast на `127.0.0.1:8080`.
- При недоступном/заблокированном платёжном процессе новые команды приостанавливаются. При сбое памяти или дисплея очередь удерживается; `pong` не снимает аппаратную ошибку. После устранения неисправности перезапусти плату и мост.
- Это снижает поверхность атаки, но не является гарантией защиты от компрометации самого компьютера, физического доступа или неисправного железа.

## Отображение и диагностика

Все служебные подписи на экране — на английском. Экран ожидания показывает `ChogCare`, предоставленную владельцем иллюстрацию, `Waiting for kindness` и актуальный статус эфира. После доната — три сцены, описанные выше, без фото инициатив. Текст белый/светло-розовый на тёмном фоне. Длинные ники и точные суммы прокручиваются один раз в пределах своей сцены без округления. Написание публичного ника сохраняется, в том числе кириллица.

Нижняя строка ожидания показывает `LIVE` с пульсирующей зелёной точкой только при работающем эфире и свежем heartbeat. Таймера нет. Состояния `STATION ONLINE` и `CONNECTING` не выдают остановленный эфир за действующий.

Частота анимации в настройках — целевые 20 кадров/с. Используется буфер полосы 240×32, а не полный 240×320: это экономит память и избегает очистки экрана между кадрами. Подход соответствует [рекомендациям Adafruit по уменьшению мерцания](https://learn.adafruit.com/adafruit-gfx-graphics-library/minimizing-redraw-flicker). Шрифт с кириллицей — из [U8g2_for_Adafruit_GFX](https://github.com/olikraus/U8g2_for_Adafruit_GFX).

`StationArt.h` содержит готовые RGB565-пиксели этой же картинки из `public/chog-donation-coin.png`. Прозрачность сведена к фону дисплея, пропорции сохранены, убраны только прозрачные поля. Два размера занимают 51 200 байт флеш-памяти и не добавляют буфер в RAM. Интернет и PNG-декодер плате не нужны. Для обычной прошивки ничего генерировать не требуется; файл уже готов. Для замены исходной картинки используется офлайн-скрипт `node scripts/build-station-art.mjs <папка-пакета-sharp>`; `--check` проверяет соответствие пикселей исходнику. На текущем компьютере пакет sharp доступен в зависимости рабочего окружения Codex, добавлять его в зависимости сайта не требуется.

Фактическую плавность, цвета и яркость надо проверить на твоём экране и через камеру. Если появились артефакты на длинных SPI-проводах, снизь `SPI_HZ` в `StationConfig.h` с `20000000` до `16000000` или `8000000`.

Если порт занят — закрой Serial Monitor, старый мост или другую программу, которая использует NodeMCU. Если экран постоянно сбрасывается — убедись, что RST экрана перенесён на D1 и больше не соединён с D0, где находится LED. Если после прошивки показано `CONNECTING`, запусти USB-мост. Если показано `STATION ONLINE`, проверь OBS/Owncast и переподключи мост после обновления его кода.

Для тестов очереди и протокола:

```powershell
npm run station:test
```

Проверка компиляции, программные тесты и USB-подтверждение показа не заменяют визуальную проверку качества картинки на подключённом стенде и через камеру.
