# Чёткая трансляция с меньшей задержкой

Сайт остаётся на Vercel, видео идёт через локальный Owncast и существующий Tailscale Funnel. Скрипт не меняет платежи, пароль, ключ трансляции, сеть или серверный кодек и не останавливает эфир.

## 1. Сохрани настройки Owncast

В своём PowerShell выполни:

```powershell
cd C:\Users\User\Documents\Codex\2026-10-07\ghb
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\configure-broadcast.ps1
```

Введи пароль **админки Owncast**, когда появится скрытый запрос. Не отправляй его в чат и не вписывай в команду. Подключение строго локальное: `127.0.0.1:8080`, без прокси и перенаправлений.

### Если пароль админки неизвестен

С согласованной короткой паузой эфира выполни:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\reset-broadcast-admin.ps1
```

Введи **новый** пароль два раза в скрытых запросах и сохрани в менеджере паролей. Скрипт принимает 14–72 символа: английские строчные и заглавные буквы, цифры и хотя бы один символ `!@#$%^&*`, без пробелов. Пароль не передаётся в чат, аргументы Windows-команды, файлы или историю команд. Штатный флаг восстановления Owncast временно содержит его в аргументах отдельного Linux-процесса — их могут видеть локальные привилегированные процессы и процессы пользователя Owncast. После подтверждения сохранения этот процесс сразу завершается; штатная служба запускается уже без пароля в аргументах. Закрывать терминал во время операции нельзя.

До остановки сервера скрипт проверяет существующую установку и создаёт согласованную SQLite-копию, включая записанные изменения WAL, в `/var/backups/chogcare-owncast` внутри Ubuntu WSL. Каталог доступен только root (`0700`), файл — только root (`0600`); копия содержит секретные настройки Owncast, её нельзя публиковать. Скрипт не восстанавливает старый неизвестный пароль автоматически. Ключ трансляции OBS, настройки видео, сайт и платежные процессы не меняются. При сбое пытается вернуть штатную службу и не объявляет успех без проверки нового пароля. Если появилось сообщение `VERIFIED`, войди в локальную админку с логином `admin` и новым паролем, затем снова выполни `configure-broadcast.ps1` для качества и задержки.

Способ восстановления подтверждён по [исходникам установленного Owncast 0.3.0](https://github.com/owncast/owncast/blob/4b09a1b11693977400fb6f6cb06a7b9891bdca6d/main.go) и [официальной инструкции](https://owncast.online/docs/configuration/runtime-flags/).

Скрипт проверяет установленную официальную версию Owncast 0.3.0, сохраняет только прежние настройки видео в `work/broadcast/owncast-video-*.json`, выставляет один выход шириной 1080 пикселей с сохранением пропорций, 30 FPS, 4500 кбит/с, звук 128 кбит/с и минимальную задержку. В текущем серверном кодеке `libx264` выбирается preset `veryfast`; другой кодек скрипт не трогает. После записи он читает настройки заново. При ошибке пытается вернуть и проверить только изменённые настройки видео и задержки. Полный ответ админки, пароли и ключи в резервную копию не попадают.

## 2. Настрой OBS

Когда будешь готов к короткой паузе, останови трансляцию в OBS и выставь:

| Настройка | Значение |
| --- | --- |
| Выходное разрешение | 1080 × 1920, если камера/сцена действительно вертикальная 9:16 |
| FPS | 30 |
| Кодировщик | NVIDIA NVENC H.264, если доступен |
| Управление битрейтом | CBR |
| Битрейт | 6000 кбит/с |
| Интервал ключевых кадров | 2 секунды |
| NVENC preset | P5 |
| Look-ahead | Выключен |
| B-frames | 0 |
| Звук | AAC, 128 кбит/с |

Если NVENC отсутствует, используй x264 с preset `veryfast`; P5 — настройка именно NVENC, не x264. Не растягивай горизонтальную сцену в вертикальную. Повышение битрейта не исправит расфокусированную вебку или текст, занимающий слишком мало пикселей в кадре.

## 3. Запусти эфир заново

Нажми «Начать трансляцию» в OBS. Настройки Owncast применяются **при следующем начале входящего эфира**: перезапуск сервера Owncast, компьютера и платежного терминала не требуется. Дождись появления картинки на сайте и проверь OBS → «Статистика»: не должно быть устойчивого пропуска кадров из-за сети или перегрузки кодировщика.

В обычном HLS даже минимальный режим даёт задержку порядка нескольких секунд; около 5 секунд — ориентир, не гарантия. Если картинка регулярно зависает, минимальный буфер может быть слишком агрессивным для текущей сети/нагрузки. Каждый зритель добавляет расход исходящего трафика, а у бесплатного Funnel есть ограничения пропускной способности.

Настройки и поведение проверены по исходникам [Owncast v0.3.0: API](https://github.com/owncast/owncast/blob/v0.3.0/webserver/handlers/admin/config.go), [формату видео](https://github.com/owncast/owncast/blob/v0.3.0/models/streamOutputVariant.go), [кодекам](https://github.com/owncast/owncast/blob/v0.3.0/services/transcoder/codecs.go) и [уровням задержки](https://github.com/owncast/owncast/blob/v0.3.0/models/latencyLevels.go). Ограничения публичного прокси описаны в [Tailscale Funnel](https://tailscale.com/docs/features/tailscale-funnel).
